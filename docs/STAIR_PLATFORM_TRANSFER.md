# 普通台阶的轮支撑转移目标

`reward_extensions.stair_platform_height: true` 在普通 STAIR 请求中使用
“接近 → 首次机身支撑 → 收轮到台面”的奖励阶段。默认关闭，需要已有
`stair_support_transfer`。Actor、动作接口、电机参数、课程采样和成功判据均不改变。

## 目标来源

`NativeStairPlatformReward` 观察原生 ToF 的 `record_responses`，只为实际接受的
ToF 请求绑定目标。沿用该次已经查询的 beam，以原 detector 的台阶索引读取下层
和上层世界高程；不额外查地形、不抽取新噪声。目标绑定 request ID 与 episode。

原生 `reference_height` 不是目标台面的世界高程，机身高度命令、带噪相对请求高度
和当前轮下地面也不能代替这个目标。没有可绑定几何的人工请求继续使用原高度目标。

## 阶段与奖励

接近时保留原高度正奖励 H。首次满足原有 STAIR 机身支撑条件后，锁存
`transfer_started`：STAIR 模式、许可机身接触、非特殊云台模式、同一物理子步
机身向上净接触力大于已有 3 N 阈值，并通过原生身份和几何有效性检查。

同一请求的后续 STAIR 子步使用：

```text
rise = target_top_world_z - target_lower_world_z
S = mean_wheels(clamp(1 - relu(target_top_world_z - wheel_bottom_world_z) / rise, 0, 1))
positive.height = S
```

这替换已有最高 1/s 的高度正奖励预算，不增加一个独立奖励项；所有成本保持原式。
轮底来自当前物理子步的真实轮圆柱几何。到达目标高度后的分数不再增长，轮高分数
也不代表轮子已越过立面或整车已完成台阶。

卸载机身支撑或接触许可变化，不会把同一请求切回 H。请求结束、换 ID、reset
清除阶段；非 STAIR 或特殊云台模式保持原奖励。没有有效目标几何时使用原式。
状态在 composer 完成 PRE-reset 时间、episode 与 control 检查后推进，再计算该
物理子步的奖励。已有 200 Hz 积分与 50 Hz 策略时钟不变。

## 设计依据与边界

原先候选仅在瞬时支撑期间把 H 替换为 S；已有真实台阶轨迹显示，它会在卸载时
返还接近 1/s 奖励。按请求保持阶段消除了这个重复切换通道。首次进入阶段仍可能
出现负奖励变化，请求结束也会更换目标；本实现没有声称全程连续或最优。

阶段不在 Actor 的 5×35 输入中。该历史跨 80 ms，没有长期记忆，因而任务仍有
部分可观测性。是否能提高“搭台后收腿、再把轮支撑转移到台面”的能力，需要正常
训练后的独立原生评价证明。保留原来的完整通过判据，不用 S 或协议完成替代它。

新绑定目标与阶段尚未写入紧凑世界模型记录，也未在想象中推进，因此世界模型
明确拒绝开启该扩展；不能直接沿用旧 replay 声称一致。生产 PPO 与 WM 的来源分别记录。

## 验证范围

`tests/test_stair_platform_reward.py` 覆盖目标接受、重置、结束、拒绝、替换、重试、
二级新请求、随机数与原生命令不变，以及真实 composer 的四子步接近/支撑/卸载积分。
非 STAIR 和其他奖励分项保持原值。原生短验证另检查实际 producer、目标、阶段
保持及高度分量；这些属于实现验证，不是技能成功证据。
